# 拓扑学习论文：可行性与创新性评估

2026-10-12 · 作者：Zx · 在线版：https://claude.ai/code/artifact/f5afaf9a-7b12-4d9d-878c-9798d450ee98

结论：实验在现有资源（两个本地 flash 模型 + 4–8 张 H20，不用付费 API）下可做，但要按精简版做；创新性中上，能否站住取决于 E0 的实证结果是否干净，而不是方法本身。

## 资源盘点与硬约束

现有资源比提案原先假设的"2 个开源家族 × 三档 + 前沿 API"更适合这篇论文：两个 flash 模型属于不同家族（DeepSeek、GLM），加上 H20 上部署的 Qwen3 系列正好凑出三个家族，这是 H2（异构抬高容量）最需要的；flash 模型调用无限，可以把最烧 token 的优化器扫描压到它们身上；8 张 H20 共 768 GB 显存，放得下 Qwen3-235B-A22B 的 FP8 版本，能力轴的最高点不用付费 API 也有一个接近前沿的模型。

| 资源 | 在实验里的角色 | 说明 |
| --- | --- | --- |
| ds-v4.1-flash、glm-5.3-flash（本地部署，调用无限） | M_mid 候选；E1/E2、E4、E5 全部优化器扫描的承载者；S_hetero 模型池的两个家族 | 具体参数量、是否带思考模式、部署并发上限待确认（见最后一节） |
| 4–8 张 H20（96 GB 显存/卡） | 部署 Qwen3-8B（1 卡）、Qwen3-32B（1 卡 BF16）、Qwen3-235B-A22B（4–8 卡 FP8）；承担 E0、S₀ 审计、E3 模型扫描 | 235B 占满整机，只用于审计与 E3 |
| 付费 API | 不用 | 能力轴最高点由 235B 或两个 flash 中更强者充当，论文写成 limitation |

必须先摸清的硬约束：

- **H20 的短板是算力不是显存。** 带宽 4 TB/s，BF16 算力约为 H100 的 1/6。MAS 运行是 prefill 密集型（每个 agent 都要读别人的输出），prefill 恰好是算力瓶颈，所以下面的吞吐估计可能偏差 2–3 倍。第一周先用 vLLM 跑一小时基准：batch 64，分别记 prompt tok/s 与 generation tok/s，再把预算表的数字换成实测值。
- **235B 是瓶颈。** 按 8 卡合计几百到一千 tok/s 估，只出现在 S₀ 审计和 E3 里，不进入优化器扫描。
- **flash 端点的吞吐决定 E1/E2 的工期。** 1.9B token 的优化器扫描，按 2k tok/s 要连续跑 11 天，按 10k tok/s 一天。
- **不用付费 API 的两个连带调整。** 工具轴改用本地检索（MuSiQue / HotpotQA 自带的候选段落，或本地 Wikipedia 的 BM25 索引）和本地代码沙箱；H5 本来就是探索性结论，少一个前沿模型点不致命。

## 精简实验方案与算力预算

合计约 8B token，其中约 5B 落在 flash 端点（免费，只受吞吐限制），H20 侧约 1,000–1,500 卡时，8 卡连续跑约两周，算上工程与返工按 4–6 周估。每次 MAS 运行仍按 6k token 估（4 个 agent），工具空间按 8k。

| 实验 | 精简后的规模 | 跑在哪 | 约 token | 约 H20 卡时 |
| --- | --- | --- | --- | --- |
| E0 pilot | Qwen3-8B；64 图 × 300 题 × 2 次 + 2 优化器 × 5 种子 × 200 评估 × 24 题 | H20 | 0.5B | ≈ 100（4 卡一天） |
| S₀ 审计 | 64 图 × 200 题 × 2 次 × 3 任务族，Qwen3-8B 与 32B；235B 只跑 2 个任务族、1 次 | H20 | 1.0B | ≈ 400，另加 235B 约 40 小时整机 |
| E1/E2 优化器扫描 | 3 个优化器（随机、GRPO 式、MCTS 式）× 5 种子 × 300 评估 × 24 题 × 3 任务族，M_mid 用一个 flash 模型 | flash | 1.9B | 0 |
| E3 模型扫描 | 5 个模型 × 3 种子 × 300 × 24 × 2 任务族；235B 降到 2 种子 × 200 评估 | H20 + flash | 1.2B | ≈ 350，另加 235B 约 40 小时整机 |
| E4 空间扫描 | 3 个额外空间 × 3 种子 × 300 × 24 × 2 任务族 | flash | 1.0B | 0 |
| E5 数据扫描 | 4 个 N × 3 种子 × 300 × 24 × 2 任务族 | flash | 1.0B | 0 |
| E6 + 交互 + E7 | 从上面的格子拟合，补少量验证格子 | flash | 1.0B | 0 |

相对提案全量版砍掉的东西，都只动覆盖面、不动主线：

- 审计空间图数 150 → 64（即 E0 的 4 节点、6 条可选前向边空间，剔除非法图）。
- 优化器 5 → 3：随机搜索、GRPO 式、MCTS 式进主实验；REINFORCE 与进化放附录。
- 任务族 4 → 3：数学（MATH 训练集抽样 / MATH-500 测试）、带本地检索的多跳问答（MuSiQue 或 HotpotQA）、一个真实协作任务族（MASBench 的 Reasoning / Scheduling 子集或 MultiAgentBench）；代码族（LiveCodeBench + 沙箱）改为可选。
- 非核心格子种子 5 → 3；235B 只做审计与 E3。
- 前沿付费 API 整个去掉，能力轴最高点由 235B 或 flash 中更强者充当。

    ◆ 挂 arXiv 预印本（Fig 1b 一出就挂）

读法：四段从左到右不按比例；E0 两周后的菱形是去留的门，通过就进全量并尽快挂预印本，不通过就回头改评估精度与审计空间；投稿按 E0 的结果在 ICML 2027（通常 1 月底截稿，从现在算只剩三个多月，没有返工余量）与 NeurIPS 2027（5 月）之间选。

## 创新性评估

方法的可信度高于它的"惊艳度"，所以论文的命运取决于 E0：能在一个格子上把四项分开、置信区间互不重叠，后面就是铺量；分不开，就不扩模型，先回头改评估精度和空间设计。

**站得住的部分。** 三篇最近的强近邻各自回答的是别的问题：MAS-Orchestra 训练一个编排器并问"MAS 何时有益"，Science of Scaling 在手工架构上拟合预测模型，Ringelmann 在固定拓扑下用相关性解释饱和；拓扑学习那一支（GPTSwarm 到 Graph-GRPO）全是提出优化器、报告精度。没有人把"学出来的拓扑"的平台期拿到一个可穷举的审计空间里、对着真正的最优做四项分账。分解恒等式本身很简单，但"四种数据角色 + 交叉拟合 + 预登记 ε 的平台期检验 + 资源匹配参照"这套协议是方法学贡献；3.6 把分账变成"继续搜 / 加题 / 扩空间 / 停"的处方并在留出格子上验证 regret，是别人没有的落点。

**会被攻击的地方与预案。**

| 审稿人会说 | 预案 |
| --- | --- |
| 这不就是 NAS 评估那套搬过来？（Yu et al. 2020；Li & Talwalkar 2019） | 他们比的是搜索算法之间的精度，没有把差距拆成估计 / 优化 / 泛化三项，也没有 MAS 特有的资源轴（工具、异构）和相关性解释。Related Work 2.4 要主动写这段。 |
| 64 张图、4 个 agent 太玩具 | 最大的观感风险。在更大的 S₁ 上证明分账的排序结论不变（哪个优化器 O 更大、E 随 N 的斜率），再用真实协作任务族证明拓扑改变的是协作过程。 |
| 恒等式太简单，理论贡献弱 | 承认它是会计恒等式，把新颖性落在发现上。能撑起论文的发现：审计空间里大部分平台期不是容量所限；随机搜索在审计空间里追平 GRPO；同质空间容量 ≤ ε 而异构空间不是；干预决策的 regret 显著低于固定规则。两条成立且数字干净就够格；一条都不成立则改写为 negative result，仍可发但命中率下降。 |
| 并发风险 | 半年内很可能有人做"编排训练何时饱和"，MAS-Orchestra 的后续尤其可能。E0 做出 Fig 1b 后尽快挂 arXiv 预印本，占住"归因平台期"这个表述。 |
| 没有前沿模型 | 能力轴最高点是 235B 或 flash 中更强者，写成 limitation；H5（强模型下退化）本来就是探索性结论。 |

## 待确认信息与下一步

两个 flash 模型的规模与部署吞吐决定 E1/E2 能不能全压在它们身上，是最先要补的信息。

- [ ] 补充 ds-v4.1-flash 与 glm-5.3-flash 的参数量、是否带思考模式（影响算力匹配）、部署并发与吞吐（tok/s）。
- [ ] 第一周：在 H20 上用 vLLM 跑一小时基准（Qwen3-8B / 32B / 235B-A22B FP8，batch 64），记 prompt 与 generation tok/s，把预算表换成实测值。
- [ ] 确认 H20 是否为本项目独占，以及 235B 整机占用的时段安排。
- [ ] 搭本地检索（MuSiQue / HotpotQA 候选段落或 Wikipedia BM25）与本地代码沙箱，确保工具轴不依赖付费服务。
- [ ] 定审计空间 S₀：4 节点固定执行顺序、6 条可选前向边，列出输入输出约束与孤立节点规则，确认合法图数量。
- [ ] 启动 E0（Qwen3-8B × 1 个任务族 × 64 图 oracle + 随机搜索 + GRPO 式，5 种子，约 100 卡时）；通过判据：四项的 CI 能区分至少两种成因、交叉拟合与单次 max 的差可量化、5 种子下平台期检验能给出结论。
- [ ] E0 通过后：把精简方案写回论文提案的 4.1 与算力预算表，补"无付费 API"的 limitation，挂 arXiv 预印本，再决定投 ICML 2027 还是 NeurIPS 2027。
